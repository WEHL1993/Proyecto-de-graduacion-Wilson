COMANDOS PARA LEVANTAR EL SISTEMA (Backend + Frontend)
=======================================================
Sistema de Análisis Predictivo (ML) - Desarrollos Comerciales del Sur, S.A.

Ejecutar todo desde la raíz del proyecto.
Requisito previo: archivo .env en la raíz (copiar de .env.example si existe).


OPCIÓN A: TODO CON DOCKER (recomendada)
---------------------------------------
Levanta postgres, backend (migraciones + seed), worker y frontend.

  docker compose -f infra/docker-compose.yml --env-file .env up -d --build

URLs:
  Frontend : http://localhost:5173
  Backend  : http://localhost:8000
  Docs API : http://localhost:8000/docs

Detener:
  docker compose -f infra/docker-compose.yml --env-file .env down

Ver logs:
  docker compose -f infra/docker-compose.yml --env-file .env logs -f


OPCIÓN B: CON MAKE (postgres + backend en Docker)
-------------------------------------------------
  make up          # levanta postgres + backend
  make migrate     # aplica migraciones
  make down        # detiene


OPCIÓN C: LOCAL SIN DOCKER (Windows / PowerShell)
-------------------------------------------------
1) Base de datos: PostgreSQL 16 corriendo en localhost:5433
   (o solo postgres con Docker):
     docker compose -f infra/docker-compose.yml --env-file .env up -d postgres

2) Backend:
     cd backend
     .venv/Scripts/python -m pip install -e .          # solo la primera vez
     .venv/Scripts/python -m alembic upgrade head      # migraciones
     .venv/Scripts/python -m uvicorn app.main:app --reload --port 8000

3) Worker (otra terminal, opcional):
     cd backend
     .venv/Scripts/python -m app.workers.main

4) Frontend (otra terminal):
     cd frontend
     npm install                                       # solo la primera vez
     npm run dev
   -> http://localhost:5173


COMANDOS ÚTILES
---------------
  make test                 # pruebas backend (pytest)
  make lint                 # ruff
  make openapi              # regenerar docs/architecture/openapi.yaml
  make frontend-test        # vitest
  make frontend-build       # tsc + vite build
  make e2e                  # pruebas E2E con Playwright (ver sección siguiente)
  cd frontend; npm run gen:api   # regenerar tipos tras make openapi

  Sin make (Windows):
    cd backend; .venv/Scripts/python -m pytest
    cd backend; .venv/Scripts/python scripts/export_openapi.py


PRUEBAS E2E CON PLAYWRIGHT (sistema completo en el navegador)
-------------------------------------------------------------
Recorren el flujo del negocio de punta a punta: login y permisos, usuarios, catálogos,
productos/kardex, ETL (Excel real + histórico sintético), entrenamiento y reentrenamiento del
modelo (con el Worker), recepción FEL, plan de carga, liquidación, compras, reportes y política.

Requisitos (una sola vez):
  - PostgreSQL en localhost:5432 con el usuario ds_user (basta el contenedor postgres:
      docker compose -f infra/docker-compose.yml --env-file .env up -d postgres
    con POSTGRES_PORT=5432 en .env)
  - backend/.venv instalado (make install)
  - cd frontend; npm install; npx playwright install chromium

Ejecutar:
  cd frontend; npm run test:e2e          # o: make e2e
  npm run test:e2e:ui                    # modo interactivo
  npm run test:e2e:report                # informe HTML (trazas y videos de los fallos)

Capturas: cada corrida guarda en frontend/e2e/capturas/ 36 imágenes con nombre de los momentos
clave (p. ej. 08-02-plan-de-carga-aprobado.png), numeradas en el orden del flujo. La carpeta se
vacía al iniciar cada corrida y también se adjuntan al informe HTML.

Usan una BD propia (ds_e2e) que se BORRA y recrea en cada corrida, la API en el puerto 8001 y
la web en el 5174: no tocan la BD ni los puertos de desarrollo. Otra BD: E2E_DATABASE_URL.
